# startups-radar

Tracks VC/accelerator portfolio pages and posts a daily digest of newly appeared
startups to a Telegram channel. Sources are managed from Telegram; scrapers for
new sources are generated by Codex CLI and self-tested before going live.

## One-time setup

1. **Bot:** create via @BotFather → token into `.env` (`TELEGRAM_BOT_TOKEN`).
2. **Channel:** create the channel, add the bot as admin with post rights.
   Channel id: forward a channel post to @userinfobot or use `@channelusername`.
3. **Admin ids:** your and your friend's numeric Telegram ids (@userinfobot) →
   `ADMIN_USER_IDS=111,222`.
4. **Keys:** `OPENAI_API_KEY` (used for enrichment AND codex CLI auth).
5. `cp .env.example .env` and fill everything in.
6. **YC scraper key:** open ycombinator.com/companies with browser devtools →
   Network → copy `x-algolia-api-key` from the algolia.net XHR into
   `scrapers/ycombinator.py` `API_KEY`.

## Deploy (remote server)

```bash
git clone <this repo> && cd startups-radar
cp .env.example .env  # fill in
docker compose up -d --build
docker compose logs -f app  # watch startup
```

## Commands (admins only, in a direct chat with the bot)

/add <name> <url> · /remove <slug> · /list · /run (digest now) · /retry <slug>

## Acceptance checklist (run once after first deploy)

- [ ] `/list` answers (bot alive, admin filter works — a non-admin gets silence)
- [ ] Register YC by inserting the source row and baselining: `/add Y Combinator
      https://www.ycombinator.com/companies` — expect "Tracking … companies baselined"
      (thousands). The generated file may be discarded in favour of the reference
      scraper: `git checkout scrapers/ycombinator.py` if codex overwrote it.
- [ ] `/run` → digest appears in the channel with health footer
- [ ] Next morning 08:00 CET → scheduled digest arrives
- [ ] `/add` a second real source (e.g. an accelerator with a simple portfolio
      page) → generated scraper self-tests and goes active
